# /infographic - инфографика уровня Джемини

> **Роль:** R6 Кодировщик в режиме оформителя: содержание и выводы - из материала; от навыка - форма, облик, графика и проверка.
> **Обещание:** `${CLAUDE_SKILL_DIR}/docs/service-clause.md`. **Мерило:** инфографика Джемини; главное отличие обычно в графике, а не в цветах.

## Где что лежит

`${CLAUDE_SKILL_DIR}` - папка этого навыка (Claude Code подставляет её сам).

| Что | Где |
|---|---|
| Движок: детали страницы и облики, сборщик, листы, иллюстрации | `${CLAUDE_SKILL_DIR}/engine/` (`looks.css`, `build.py`, `sheet.py`, `illus.py`, `gen_image.py`, `assets/`) |
| Свои фирменные облики (фирменные шрифты, логотипы) | папка из `IG_BRAND_DIRS`, по умолчанию `$IWE_WORKSPACE/DS-strategy/local/infographic-brands/` - **только локально**, в хранилища не кладу; в `look.json` облика - название, «для чего» (`use`), шрифты и `palette` (слова палитры для модели картинок) |
| Локальная модель рисования | окружение `~/.local/share/iwe-imagegen/venv`, сжатые модели `~/.local/share/iwe-imagegen/models/`; установка - README навыка. Нет окружения - шаг 5 пропускаю, графика из шага 4 остаётся |
| Образцы | `${CLAUDE_SKILL_DIR}/examples/` (узел с графикой `1-obzor`, цикл, пирамида, матрица 2×2) |

## Шаг 1. Материал, читатель, главная мысль

1. Прочитать материал целиком. Источник - проверенный документ пилота, а не чужая картинка (инфографика Джемини по тем же данным может содержать его домыслы).
2. Протокол или черновик агента: места «толкование агента» и неподтверждённые - **не выдавать за решения**; нерешённое - отдельным блоком «Не решено».
3. Читатель: назвал пилот - берём; не назвал - выбираю сам и называю выбор (шаг 3).
4. **Главная мысль - одна фраза** (подзаголовок или лента контекста), **главная цифра** - в шапку. 3-7 блоков; больше - режу.

## Шаг 2. Форма блока - по устройству материала

| Устройство материала | Форма | Деталь страницы |
|---|---|---|
| 2-4 ключевых показателя | крупные цифры | `ig-stats` › `ig-card ig-stat` |
| Суммы и сроки «от-до» | полосы на общей шкале | `ig-ranges` (`--max`) › `ig-range` (`--from`, `--to`) |
| Доля от целого | кольцо | `ig-donut` (`--p`) |
| Шаги, порядок действий | цепочка | `ig-chain` › `ig-step` |
| Варианты и выбор | колонки «за/против» | `ig-compare` › `ig-col` (`is-pick`), `li[data-mark=plus|minus]` |
| Что где стоит и куда идёт | схема двух групп | `ig-scheme` › `ig-group`, `ig-bridge` › `ig-link`, `ig-under` |
| Решения с эффектом | рычаги | `ig-levers` › `ig-lever` + `b.ig-delta` |
| Даты и вехи | линия времени | `ig-timeline` › `li` (`time`, `b`, `span`) |
| Перечень проектов, решений, статей | карточки с панелью-картинкой | `ig-features` › `ig-card ig-feature` › `ig-art`, `ig-feature-body`, `ig-feature-badges` |
| «Что есть ↔ что решить» вокруг одного предмета | узел | `ig-hub` › 2 × `ig-hub-col` (карточки в `ig-hub-item`) + `ig-hub-center` |
| **Итоги, обзор темы: центр и 4-6 направлений** | **ментальная карта** | `ig-mindmap` › `ig-mm-backdrop`, `svg.ig-mm-links`, 2 × `ig-mm-col` › `ig-card ig-mm-node` (`data-img`, `ig-mm-tag`, `h3`, `ul`), `ig-mm-center`; связи рисует сборщик |
| Ритм, круговорот | цикл | `ig-cycle` (`--n`) › `ig-cycle-center`, `ig-cycle-node` (`--i`), `ig-cycle-arrow` (`--i`) |
| Выбор по вопросам «да/нет» | дерево решений | `ig-decide` › `ig-ask`, `ig-yes`, `ig-out`, `ig-no`, `ig-final` |
| Слои, нижний - основа | пирамида | `ig-pyramid` (`--n`) › `li` › `b` + `div` |
| Выбор по двум осям | матрица 2×2 | `ig-matrix` › `ig-ax-y`, `ig-quads` › `ig-quad`, `ig-ax-x`; `ig-chips` |
| Риск, совет; вопросы, чек-лист | выноска; список | `ig-callout[data-kind=risk|tip]`; `ig-list` |

Таблица в материале - не таблица на странице: цены → `ig-ranges`, «что где стоит» → `ig-scheme`, «вариант/плюсы/минусы» → `ig-compare`.

## Шаг 3. Облик - по читателю и теме

| Облик | `data-look` | Когда |
|---|---|---|
| **Фирменный** | имя папки бренда | материал организации, чей облик есть в папке брендов (её `use` в `look.json`) - по умолчанию для её материалов |
| Строгий | `strict` | руководство, деньги, официальное |
| Яркий | `bright` | команда, обучение, «как у Джемини» |
| Журнал | `editorial` | аналитика и обзор для руководителя |
| Чертёж | `blueprint` | ИТ-архитектура, схемы серверов |
| Ночной | `night` | показатели, проектор в тёмном зале |
| Акварель / Эскиз | `watercolor` / `sketch` | идея «на пальцах» / замысел у доски |
| Поп / Стимпанк / Фэнтези | `pop` / `steampunk` / `fantasy` | анонс / «как устроено» / история проекта |

Какие фирменные облики есть - `python3 -I ${CLAUDE_SKILL_DIR}/engine/build.py --help` (список `--look`). Фирменный облик - по брендбуку организации, без аляповатости: один фирменный цвет на страницу и его оттенки, одна сплошная плитка в ряду, логотип без эффектов. Пёстрые ряды из разных цветов - брак. **Перед сборкой - одна строка пилоту:** «Форма - …, облик - …, потому что …». Пилот не уверен - `--all-looks` с переключателем.

## Шаг 4. Графика - на каждом экране

Страница из текстовых карточек - брак. Источники графики, по убыванию веса:

1. **Картинки локальной модели** (`<i data-img="art/x.png">`) - для шапки, центра карты, панелей карточек, фирменных страниц. Шаг 5.
2. **Векторные иллюстрации** (`<i data-illus="имя">`, красятся в цвета облика): servers, server-pair, database, documents, hub, chart, cloud, key-lock, shield, people, factory, warning, money.
3. **Объёмные картинки** Fluent 3D (`<i data-3d="имя">`, 38 штук: computer, key, lock, stopwatch, gear, factory, chart-up, calendar, bulb, money, shield, hourglass, warning, check, rocket, handshake, robot, cat, truck, globe и др.; полный список - `ls ${CLAUDE_SKILL_DIR}/engine/assets/emoji3d/`).
4. **Ряд пиктограмм** `<i data-pict="user" data-n="50" data-on="20">`; **значки с числами** `ig-count`, `ig-cal`, `ig-timer` (`--v`); **лента** `p.ig-banner`; **прогресс** `ig-progress` (`--v`).

Значки строк - `<i data-icon="имя">` из 56 значков Lucide (`ls ${CLAUDE_SKILL_DIR}/engine/assets/icons/`); неизвестный значок сборщик назовёт.

## Шаг 5. Картинки моделью (FLUX.2 Klein 4B на Маке)

Только если окружение модели установлено (README навыка). Таблица описаний `prompts.tsv` рядом со страницей - через табуляцию: `имя  стиль  описание  [ширина  высота]`. Стили: `iso` (изометрия, по умолчанию), `flat`, `character`, `scene`, `backdrop` (фоновая панорама, фон не вырезается; 1536×864). Описание - **по-английски, предмет без текста**: весь текст ставит страница.

```bash
cd <папка страницы>
~/.local/share/iwe-imagegen/venv/bin/python "${CLAUDE_SKILL_DIR}/engine/gen_image.py" \
    --batch prompts.tsv -o "art-{look}" --look bright,night     # всю таблицу, на каждую палитру
# одна картинка: ... gen_image.py "a key ring next to a shield" -o art/hero.png --look bright --seed 11
```

- 35-50 с на картинку на M4 24 ГБ, фон - 80 с; восемь картинок - около 6 минут: запускать в фоне. Готовые картинки пропускаются (`--force` - перерисовать), прерванный прогон просто запускается снова.
- **Каждую картинку смотрю глазами** (Read по PNG). Не тот предмет («браслет вместо ключей») - точнее описание («a bunch of three metal keys on a single key ring») и 2 зерна (`--seed 11`, `23`), беру лучшее.
- Белые части предмета, касающиеся фона, вырезаются вместе с ним - просить цветные детали.
- Всё считается на Маке, наружу ничего не уходит. Модели - сжатые копии (пересжатие при каждом запуске уводит Мак в подкачку: 18-20 мин вместо 2). Запасная модель - `--model z-image-turbo` (2 мин). Qwen-Image 2.1 - некоммерческая лицензия, не брать.

## Шаг 6. Исходник страницы

`<имя>.src.html` рядом с картинками. Только детали из шага 2, без своих стилей; цвет детали - `data-tone="1..5"`. Каркас:

```html
<!doctype html>
<html lang="ru" data-look="bright">
<head><meta charset="utf-8"><meta name="viewport" content="width=device-width, initial-scale=1">
<meta name="ig-type" content="Ментальная карта"><title>…</title></head>
<body><main class="ig">
  <header class="ig-hero"><p class="ig-kicker">Жанр · дата</p>
    <div><h1>Заголовок</h1><p class="ig-lead">Главная мысль.</p></div>
    <div class="ig-hero-art"><i data-img="art-{look}/hero.png"></i></div></header>
  <p class="ig-banner"><b>Главное:</b> …</p>
  … детали шага 2 …
  <footer class="ig-foot"><p>Источник и дата. Картинки нарисованы локальной моделью на этом компьютере.</p></footer>
</main></body></html>
```

- **Один исходник - все облики:** `{look}` в пути картинки сборщик заменяет на облик сборки (`art-{look}/hero.png` → `art-bright/hero.png`). Картинки - только из папки страницы.
- Каждая цифра есть в материале; посчитанная мной - с пометкой «расчёт». Оценки - «от-до». Подписи короткие (карточка - до 8 слов). Длинных тире нет. Ответственный - фамилия с инициалами, отчество не угадываю.
- Логотипов чужих марок (Google, Джемини) нет: берём язык оформления, не марку.

## Шаг 7. Сборка и проверка

```bash
python3 -I "${CLAUDE_SKILL_DIR}/engine/build.py" <имя>.src.html -o <имя>.html --look <облик> --shot <имя>.png
```

Код 1 - неизвестный значок, картинка, облик или внешний адрес. Код 2 (с `--shot`) - не загрузилась кириллица, текст вылез из рамки на 1280 или на телефоне 390, прокрутка вбок: **чиню, не сдаю**. Затем **смотрю снимок сам**: автопроверка не видит наездов, тесных колец, неудачных картинок.

## Шаг 8. Листы и сравнения

```bash
python3 -I "${CLAUDE_SKILL_DIR}/engine/sheet.py" page.src.html -o лист.png              # одна страница во всех обликах
python3 -I "${CLAUDE_SKILL_DIR}/engine/sheet.py" a.src.html b.src.html c.src.html -o лист.png --cols 3 --tile 600 --crop 1500   # разные страницы
```

Сравнение «до/после» или «вариант A/B» - две картинки рядом с подписями; по просьбе - одним длинным снимком или отдельными картинками.

## Шаг 9. Передача

- **Куда:** материалы организаций, персональные данные, фирменные облики - `DS-strategy/local/` (вне git); прочее - в папку рабочего продукта.
- **Пилоту:** открыть страницу в браузере (`open`), снимок - выделить в Finder (`open -R`); в чате - строка выбора формы и облика и что взято из какого источника.
- **Людям** - только после фактчека пилота; протокол-черновик - прямо назвать, что не подтверждено.
- «Строже», «ярче», «в фирменном стиле» после показа - пересборка с `--look`, содержание не трогаю.

## Уроки, которые уже стоили времени

- Слой с `z-index: -1` (штриховка, пятна) ложится поверх фона карточки, если карточка сама создаёт контекст наложения (`isolation`, `transform`).
- Правила бренда - только в папке бренда, не в общем `looks.css` (общий файл уходит в хранилище).
- Фоновая дымка над рисунком - лёгкая и только в центре: рисунок должен читаться.
- Chrome без окна не уже 500 точек: «телефон» проверяется сжатием тела страницы до 390.

## Чего навык не делает

- Не проверяет факты материала: ошибка источника перейдёт на страницу.
- Не ставит текст внутрь картинок модели: кириллица там ломается, а цифры нельзя поправить.
- Не заменяет презентацию со слайдами.

# Инфографика: облики и сборщик

Движок навыка `/infographic` (`SKILL.md` в корне хранилища). Обещание, сценарии
и роль — `docs/service-clause.md`.

## Что здесь

| Файл | Что делает |
|---|---|
| `looks.css` | детали страницы (`ig-hero`, `ig-stats`, `ig-ranges`, `ig-scheme`, `ig-cycle`, `ig-decide`, `ig-pyramid`, `ig-matrix`, …) и десять обликов: `strict`, `bright`, `watercolor`, `blueprint`, `night`, `editorial`, `pop`, `steampunk`, `fantasy`, `sketch`. Детали читают только переменные; облик — набор переменных и немного правок под `html[data-look=…]` |
| `build.py` | собирает исходник в одну страницу: встраивает шрифты облика, значки, фильтры акварели; отказывает на внешних адресах. `--shot` делает снимок в Chrome без окна и проверяет вёрстку |
| `sheet.py` | макетный лист: одна страница во всех обликах или несколько страниц рядом — одна картинка PNG |
| `illus.py` | генератор изометрических иллюстраций в `assets/illus/` (сервер, базы, документы, узел, график, облако, ключ с замком, щит, люди, завод, предупреждение, деньги): примитивы «ящик», «цилиндр», «лист»; цвета не зашиты, их задают классы `f1-f3`/`g1-g3`/`o`/`ln` из `looks.css` |
| `gen_image.py` | рисует картинку локальной моделью (mflux на Apple Silicon): описание + стиль + палитра облика, белый фон вырезается заливкой от краёв, картинка обрезается по содержимому. Запуск - питоном окружения `~/.local/share/iwe-imagegen/venv` (mflux 0.22, Pillow); модели `flux2-klein-4b` (по умолчанию, 4 шага) и `z-image-turbo` (8 шагов). Модели держать сжатыми копиями: `mflux-save --model <модель> --quantize 4 --path ~/.local/share/iwe-imagegen/models/<модель>-q4`, скрипт берёт их сам; пересжатие при каждом запуске на 24 ГБ уводит Мак в подкачку (Z-Image: 18-20 мин против 2 мин). Пакетный режим: `--batch prompts.tsv -o "art-{look}" --look bright,night` (таблица «имя, стиль, описание [, ширина, высота]», готовые картинки пропускаются). В страницу картинка попадает через `<i data-img="путь">`; `{look}` в пути сборщик заменяет на облик сборки - один исходник на все бренды |
| `library.py` | библиотека готовых картинок вне хранилища (`IG_LIBRARY_DIR`, по умолчанию `$IWE_WORKSPACE/DS-strategy/local/infographic-library`): `add` кладёт картинки папки страницы с описаниями из `prompts.tsv` (одна и та же картинка - один раз), `tag` - русские подписи, `find` - подходящие по словам, сначала в облике страницы, `take` - копия в папку новой страницы, `sheet` - страница просмотра. без своей библиотеки берёт `library/` хранилища. Только стандартная библиотека Python: работает и без окружения модели |
| `library_publish.py` | выгружает общие облики своей библиотеки в `library/` хранилища: WebP до 512 точек (~30 КБ вместо ~300 КБ PNG), каталог и страница просмотра; фирменные облики отказывает выкладывать, уже выложенное не трогает - запускать после каждой ночи. Нужен Pillow (питон окружения модели) |
| `fetch_assets.py` | разовая докачка шрифтов и значков в `assets/` (результат лежит в git, сборке сеть не нужна) |
| `assets/fonts/` | Onest, JetBrains Mono, Inter, Nunito, Caveat, Playfair Display, Unbounded, Old Standard TT, PT Serif, Ruslan Display, Alegreya, Neucha, Pangolin — наборы cyrillic, latin, latin-ext (в latin-ext знак рубля) |
| `assets/icons/` | 56 значков Lucide 0.460.0 |
| `assets/emoji3d/` | 38 объёмных картинок Microsoft Fluent Emoji 3D (MIT, `LICENSE.txt` рядом) |

## Сборка

```bash
# Python 3.9+ без сторонних пакетов; для --shot нужен Google Chrome (другой путь - переменная CHROME)
python3 -I build.py page.src.html -o page.html                    # облик из <html data-look>
python3 -I build.py page.src.html -o page.html --look watercolor  # другой облик
python3 -I build.py page.src.html -o page.html --all-looks        # все облики + переключатель
python3 -I build.py page.src.html -o page.html --shot page.png    # + снимок и проверка
```

Коды выхода: 0 — собрано (и проверено, если `--shot`); 1 — ошибка сборки (значок, адрес,
облик); 2 — проверка в Chrome нашла проблему вёрстки.

**Как устроена проверка.** Страница сама после загрузки шрифтов пишет на `<html>` высоту,
незагруженную кириллицу облика, строки текста, вышедшие из своей рамки, и самую правую
точку элементов. Сборщик читает это из `--dump-dom`. Chrome без окна не бывает уже 500
точек, поэтому телефон (390) проверяется так: окно 500, тело страницы сжато до 390,
граница проверки — 390. Декоративные пятна и блики (псевдоэлементы) не проверяются
намеренно: в акварели они и должны выходить за рамки, страница их обрезает по краю.

**Слои в CSS — ловушка, на которой уже ошибались.** Штриховка эскиза и пятна акварели — псевдоэлементы с `z-index: -1`. Если карточка сама создаёт контекст наложения (`isolation`, `transform`), такой слой рисуется поверх её фона, а не под ним. В эскизе у карточек поэтому `isolation: auto`, а у повёрнутых узлов цикла тень выключена.

## Фирменные облики

Папка с `look.json` (имя, название, «для чего», шрифты, палитра для модели картинок), `look.css`, `fonts.css` и файлами, на которые они ссылаются (`url(logo.svg)` сборщик превращает во встроенные данные). Ищутся в `IG_BRAND_DIRS` (через `:`), по умолчанию в `$IWE_WORKSPACE/DS-strategy/local/infographic-brands/`. В это хранилище фирменные шрифты и логотипы не кладутся: обычно они лицензированы организации. Как собрать свой облик - в README в корне.

## Лицензии

Шрифты — SIL Open Font License 1.1 (Google Fonts), тексты лицензий всех семейств в `assets/fonts/OFL.txt`. Значки — Lucide, ISC License, `assets/icons/LICENSE.txt`. Объёмные картинки — Microsoft Fluent Emoji, MIT, `assets/emoji3d/LICENSE.txt`. Загрузчик `fetch_assets.py` скачивает лицензии вместе с файлами.
Обе разрешают встраивание в документы и передачу.

## Тесты

`tests/test_infographic.py` (запуск из корня: `python3 -m unittest tests/test_infographic.py`): встраивание значков, шрифтов и картинок, отказы сборщика, фирменный облик из папки, макетный лист, таблица описаний для модели; с Chrome — что проверка ловит вылезающий текст и пропускает чистую страницу.
